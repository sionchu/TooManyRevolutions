## 1. Mission

Implement the smallest authoritative runtime slice that binds an authored RebellionPersistenceProfile to a newly created T018 rebellion Conflict without inventing operational evidence.

Required semantic chain:

```text
T018 creates a new rebellion Conflict
+ exactly one authored RebellionPersistenceProfile matches its Country/Faction pair
+ existing REBELLION_STARTED GameEvent is emitted
-> exactly one Conflict-scoped persistence episode identity/provenance record
-> lifecycle meaning: bootstrap identity only
-> no claim of continued operational capacity
-> no Conflict outcome or territorial mutation
-> strict persistence V8 / replay closure
```

This task does NOT implement operational evidence, collapse evidence, a settlement process, autonomous persistence decisions, or a Gate 1F pacing repair.

## 2. Runtime state

Add only a minimal Conflict-scoped bootstrap record. Semantics equivalent to:

```ts
interface RebellionOperationalPersistenceEpisode {
  readonly conflictId: ConflictId;
  readonly profileId: RebellionPersistenceProfileId;
  readonly countryId: CountryId;
  readonly factionId: FactionId;
  readonly bootstrappedAtTick: number;
  readonly sourceEventId: EventId;
}
```

Store at most one episode per rebellion Conflict in a deterministic WorldState record keyed by ConflictId, e.g. `rebellionPersistenceEpisodes`.

Do not add:

- evidence IDs or evidence collections;
- current active channel state;
- a persistence boolean/strength/progress/readiness value;
- collapse/suppression state;
- settlement state;
- timers/durations/decay/cooldowns;
- LandHex/front/Region targets;
- narrative fields.

The episode means only: "this T018-created rebellion Conflict was bootstrapped under this authored profile and this REBELLION_STARTED provenance." It is NOT positive evidence that the rebellion continues to have operational capacity.

A resolved rebellion may retain the bootstrap episode as historical provenance. Do not use episode presence as `Conflict.status === active` authority.

## 3. Bootstrap owner and atomicity

Bootstrap only at the existing T018 rebellion-creation writer when a NEW rebellion Conflict is successfully created.

Rules:

1. Find the authored persistence profile by the exact rebellion Country/Faction pair.
2. Static FIX22 validation guarantees at most one exact pair profile; runtime code must still fail/no-op safely rather than choose by array order if an inconsistent untrusted scenario somehow presents ambiguity.
3. Reuse the existing `REBELLION_STARTED` GameEvent emitted for that Conflict. Do not create a second rebellion-start event.
4. The episode's `sourceEventId` is exactly that event ID and `bootstrappedAtTick` is the same tick.
5. Conflict creation + start event + episode bootstrap must be one deterministic simulation-step result. Do not partially create an episode if Conflict/start-event creation fails.
6. T018 existing dedup remains authoritative; repeated eligibility must not create a second Conflict, second episode, or duplicate start event.
7. If no matching profile exists, preserve current T018 behavior exactly and create no episode.

Do not bootstrap episodes merely because an active rebellion already exists in `ScenarioDefinition.initialConflicts`. There is no T018 runtime creation event for such an initial snapshot, so fabricating a bootstrap provenance would be incorrect. Initial active rebellions remain unchanged unless a later separately authorized initial-runtime authoring contract is added.

## 4. No operational evidence writer in FIX23

FIX23 must not decide whether `organizationalContinuity`, `commandContinuity`, `logisticsAccess`, or `externalSupport` currently exists.

Do not add an ActionRecord or GameEvent type that claims one of those facts. Do not infer evidence from:

- Faction organization/resources/influence/grievance/currentStrategy;
- Region unrest/radicalism/organization/scarcity/stateControl;
- Country militaryPower/stateCapacity/legitimacy/instability/stateContinuity;
- LandHex control or front edges;
- Agenda/read models;
- elapsed time/cadence;
- RNG;
- channel names;
- unstructured player/heuristic/LLM judgment.

The next task after successful FIX23 must ground the source of operational evidence before any evidence producer/writer is implemented.

## 5. Existing-system boundaries

Preserve all of the following:

- T018 remains the only rebellion-creation owner.
- `suppressIneligibleRebellions()` remains unchanged in semantics; if it later resolves a bootstrapped rebellion, the bootstrap episode may remain as provenance and must not block the existing typed resolution.
- T021 remains the only simplified territorial-conflict path; FIX23 writes no LandHex and no front state.
- `LandHex.controller` remains sole physical territorial authority.
- no `NO_ACTIVE_FRONT_EDGE -> peace`.
- no `0 faction LandHex -> defeat`.
- no direct Conflict status/outcome writer from the persistence episode.
- no State Dissolution writer; T023 remains sole owner.
- no T022 Order Consolidation writer.
- settlement/demobilization/suppression closure remains a separate domain.
- coup coordination and FUND_MOVEMENT behavior remain unchanged.
- LLM never mutates authoritative state directly.

## 6. Provenance and runtime closure

Runtime closure must verify at minimum for every persisted episode:

- record key equals `episode.conflictId`;
- referenced Conflict exists and `kind === "rebellion"`;
- episode Country/Faction participate in that Conflict;
- referenced profile exists and exactly matches episode profileId/Country/Faction;
- the profile is still valid FIX22 authoring for that Country/Faction;
- `bootstrappedAtTick` is a non-negative integer not beyond WorldState.tick;
- `sourceEventId` is non-empty;
- no duplicate episode identity for one Conflict.

Persistence/event-store closure must additionally verify `sourceEventId` references exactly the existing `REBELLION_STARTED` event for the same Conflict/Country/Faction and tick, using the event's actual existing actor/target/payload contract rather than inventing a second event schema.

Do not require an operational evidence event in FIX23.

## 7. Persistence V8

Because a new authoritative WorldState field is added, advance persistence exactly once:

```text
SIMULATION_SNAPSHOT_FORMAT_VERSION: 8
SerializedSimulationSnapshotV8
SerializedWorldStateV8
```

V8 must serialize/deserialize/canonicalize `rebellionPersistenceEpisodes` and preserve uninterrupted vs save/load replay equality.

Strict V8 decoding/closure must reject at minimum:

- missing `rebellionPersistenceEpisodes` field;
- malformed/non-object episode map;
- empty/malformed Conflict/profile/Country/Faction/source-event IDs;
- key/record Conflict ID mismatch;
- missing or non-rebellion Conflict;
- Conflict participant mismatch;
- missing/mismatched authored profile;
- invalid bootstrap tick;
- missing/mismatched `REBELLION_STARTED` source event;
- source event tick or Conflict/Country/Faction provenance mismatch;
- duplicate/corrupt episode identity.

Do not silently migrate V7 to V8. If there is no explicit migration framework, reject older snapshot formats consistently with current strict persistence behavior.

Update T024/persistence/replay coverage accordingly.

## 8. Initial WorldState semantics

`createInitialWorldState()` must contain the deliberate empty V8 runtime shape:

```text

```

Static FIX22 authoring must NOT be copied into this map. In particular:

- a scenario with profiles but no runtime-created rebellion starts with `{}`;
- an authored initial rebellion Conflict does not auto-create an episode;
- absent and empty FIX22 authoring remain behaviorally equivalent apart from the common deliberate V8 empty field.
