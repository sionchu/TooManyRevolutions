## 1. Mission

Implement only the smallest static, scenario-owned Rebellion Persistence authoring seam accepted by F05_FIX21.

The seam defines which typed operational channels may later be referenced as authoritative evidence for a specific Country/Faction rebellion. It does **not** create runtime evidence, a persistence episode, a Conflict outcome, a territorial effect, or a pacing repair.

Required semantics:

```text
Scenario-owned channel/profile authoring
-> strict static validation
-> no WorldState copy
-> no ActionRecord/GameEvent writer
-> no T018/T021 behavior change
-> persistence V7 unchanged
```

## 2. Static types

Use repository-consistent branded IDs and general technical names equivalent to:

```ts
type RebellionOperationalChannelKind =
  | "organizationalContinuity"
  | "commandContinuity"
  | "logisticsAccess"
  | "externalSupport";

interface RebellionOperationalChannelDefinition {
  readonly id: RebellionOperationalChannelId;
  readonly countryId: CountryId;
  readonly kind: RebellionOperationalChannelKind;
  readonly name: string;
}

interface RebellionPersistenceProfile {
  readonly id: RebellionPersistenceProfileId;
  readonly countryId: CountryId;
  readonly factionId: FactionId;
  readonly channelIds: readonly RebellionOperationalChannelId[];
}
```

Add optional ScenarioDefinition fields equivalent to:

```ts
readonly rebellionOperationalChannels?: readonly RebellionOperationalChannelDefinition[];
readonly rebellionPersistenceProfiles?: readonly RebellionPersistenceProfile[];
```

A channel is an **allow-listed evidence contract**, not current evidence. A profile is an identity-scoped list of allowed channels, not a weighted set, quorum, majority, score, threshold, readiness value, or pre-authored result.

The channel `name` is authoring/presentation text only and must never be used as a simulation branch key.

## 3. Identity and capability semantics

- A persistence profile is scoped to exactly one `(countryId, factionId)` pair.
- At most one profile may exist for an exact `(countryId, factionId)` pair.
- Pair identity must use exact typed identity, not a delimiter-joined string key. A regression test must prove delimiter-like ID text cannot create a false duplicate collision.
- `factionId` must reference an existing Faction belonging to `countryId`.
- The Faction must have the existing authored `rebellion` political-crisis capability.
- A channel referenced by a profile must belong to the same Country as the profile.
- `channelIds` must be non-empty and contain unique channel IDs.
- Array order has no gameplay semantics.

Do not infer profiles from Faction organization/resources/grievance/currentStrategy, Region state, LandHex control, Agenda, ideology, or any other runtime value.

## 4. Static validation

Integrate a focused static validator into the existing ScenarioDefinition validation boundary. Reject at minimum:

1. empty operational channel ID;
2. duplicate operational channel ID;
3. unknown channel Country;
4. unsupported/free-form channel kind;
5. blank or whitespace-only channel name;
6. empty persistence profile ID;
7. duplicate persistence profile ID;
8. unknown profile Country;
9. unknown profile Faction;
10. profile Faction/Country mismatch;
11. profile Faction lacks authored `rebellion` capability;
12. duplicate exact `(countryId, factionId)` profile pair using delimiter-safe identity logic;
13. empty `channelIds`;
14. duplicate channel ID inside one profile;
15. unknown referenced channel ID;
16. referenced channel belongs to a different Country.

The static schema must not contain or accept fields whose semantics encode:

- current/initial persistence evidence;
- active/inactive channel state;
- final `Conflict` outcome;
- persistence strength/progress/readiness;
- weights, quorum, majority, score, threshold, probability;
- timer, duration, cooldown, countdown, decay;
- LandHex/Region target or controller mutation;
- front-edge authoring;
- settlement terms, acceptance, implementation, demobilization, suppression closure;
- story/narrative schedule.
