## 1. Mission

Implement one minimal deterministic runtime vertical slice for an **already-active coup Conflict** with an authored FIX17 coordination profile:

```text
active coup Conflict
+ scenario-owned CoupCoordinationProfile
+ explicit typed required-node response ActionRecord
-> authoritative sparse attempt-local response state
-> deterministic node-response GameEvent provenance
-> evaluate authored necessary-set
-> existing applyConflictOutcome() sink
-> statusQuo OR nonterminal governmentTransition OR remain active
-> strict versioned persistence/replay
```

This task must make the accepted FIX16/FIX17 semantics executable **when explicit responses are supplied**. It must not invent an autonomous response source merely to manufacture Gate 1F pacing.

No numeric coup score, loyalty meter, coordination meter, majority, timer, random roll, territorial coup mechanic, or scalar inference is allowed.

## 2. Runtime state: sparse decisive responses only

Use the narrowest authoritative runtime state consistent with repository conventions. Semantics must be equivalent to:

```ts
type CoupCoordinationAlignment = "incumbent" | "coup";

interface CoupCoordinationResponseState {
  readonly conflictId: ConflictId;
  readonly nodeId: CoupCoordinationNodeId;
  readonly alignment: CoupCoordinationAlignment;
  readonly actionId: ActionId;
  readonly eventId: EventId;
  readonly respondedAtTick: number;
}

WorldState.coupCoordinationResponses:
  Record<ConflictId, Record<CoupCoordinationNodeId, CoupCoordinationResponseState>>
```

Exact naming may follow repository style, but preserve these semantics.

### `uncommitted`

`uncommitted` is **not stored as a mutable value and is not a progress state**. It means only:

```text
required node has no accepted decisive response for this coup Conflict
```

Therefore:

- do not create an `uncommitted` writer;
- do not create a countdown/progress value;
- do not infer alignment from Country/Faction/Government scalars, ideology, currentStrategy, Agenda, Region stateControl, LandHex control, elapsed time, or node name;
- do not copy node names, weights, force values, ranks, or a general command structure into WorldState;
- sparse absence is the authoritative representation of `uncommitted`.

The scenario-owned FIX17 profile remains the authority for the required-node set and successor Government. Runtime state records only actual accepted decisive responses/provenance.

## 3. Typed response action

Add exactly one bounded action type:

```text
COUP_COORDINATION_RESPONSE
```

Use schema version `1` unless an existing repository convention requires another value.

Payload semantics:

```ts

  conflictId: ConflictId;
  nodeId: CoupCoordinationNodeId;
  alignment: "incumbent" | "coup";
}
```

Exact payload keys only. Reject extra/missing keys, empty IDs, unsupported schema version, and `alignment: "uncommitted"`.

A response ActionRecord is the only authorized alignment writer in F05_FIX18.

Do **not** add the coup node to `Faction`, `Government`, military units, or a generic actor framework. `ActionRecord.source` remains execution/proposal provenance and must not be reinterpreted as the coup node identity; `nodeId` is the explicit coordination actor identity.

### Runtime/business validation

Before mutating response state, deterministically reject/no-op with repository-consistent rejection provenance at minimum when:

1. payload/schema invalid;
2. Conflict does not exist;
3. Conflict is not active;
4. Conflict kind is not `coup`;
5. no unique FIX17 profile matches the coup Conflict's Country/Faction participants;
6. response node is not in the matched profile's authored `requiredNodeIds`;
7. node already has a decisive response for this Conflict, whether same or different alignment;
8. required static node/profile references are no longer scenario-valid;
9. a transition-producing final response would use a successor Government that is missing, foreign-Country, or equal to the Country's **current** Government at actual resolution time.

Do not auto-retarget a stale successor Government. Do not invent a replacement Government.

Domain-invalid accepted inputs may follow the repository's existing intervention/political-response pattern: preserve the ActionRecord in the run log, emit explicit deterministic rejection evidence if that is the established convention, and leave authoritative coup response state unchanged.

## 5. Outcome evaluation

After each successfully applied response, evaluate **only the authored necessary-set** from the matching FIX17 `CoupCoordinationProfile`.

Canonical rule:

```text
ANY required node explicitly incumbent
  => statusQuo

ELSE IF ALL required nodes explicitly coup
  => governmentTransition to authored successorGovernmentId

ELSE
  => Conflict remains active
```

Properties:

- required-node insertion order has no semantics;
- no majority/quorum/weight/score;
- one `incumbent` response is decisive status quo;
- partial `coup` responses do not resolve;
- all required `coup` responses resolve only after runtime successor freshness validation;
- later responses to an already-resolved Conflict are rejected/no-op;
- same-tick multiple actions obey existing global ActionRecord sequence order.

### Existing result sink only

Use the existing typed `applyConflictOutcome()` path for both:

```text
{ kind: "statusQuo", ... }
{ kind: "governmentTransition", ... }
```

Do not directly mutate `Country.currentGovernmentId` in new coup code.

For `governmentTransition`:

- `countryId` remains unchanged;
- successor Government must be the authored same-Country Government;
- winner may use the existing coup Faction winner representation if required by the sink;
- Government transition remains nonterminal.

For `statusQuo`, do not damage state continuity or territorial authority.

Use the accepted response-event IDs as causal evidence for the outcome event if the existing `applyConflictOutcome()` `causeIds` contract supports it. Stable ordering is required.
