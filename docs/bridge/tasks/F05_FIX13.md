## 5. Runtime feasibility and duplicate rules

A targeted commitment may be created only when all are true at application time:

1. Faction exists;
2. scenario has exactly one matching validated authoring profile for that Faction;
3. action `targetRegionId` exactly matches the profile;
4. action `resourceAmount` exactly matches the authored profile;
5. target Region exists and remains within the profile's valid same-Country political target boundary;
6. current derived available Faction resources are at least the authored amount;
7. no active same-actor/same-target FUND_MOVEMENT commitment already exists;
8. run is not terminal.

The static validator intentionally did not compare `resourceAmount` to initial Faction resources. This task must perform current-state feasibility at runtime.

- an active same-actor/same-target commitment must prevent a second commitment;

- manual duplicate inputs may be rejected/no-op deterministically, but rejection/lifecycle events must not be counted as pacing merely because they occur.
