## Mission

Implement the smallest deterministic static contract equivalent to:

```ts
interface CoupCoordinationNodeDefinition {
  readonly id: CoupCoordinationNodeId;
  readonly countryId: CountryId;
  readonly name: string;
}

interface CoupCoordinationProfile {
  readonly countryId: CountryId;
  readonly coupFactionId: FactionId;
  readonly requiredNodeIds: readonly CoupCoordinationNodeId[];
  readonly successorGovernmentId: GovernmentId;
}
```

`ScenarioDefinition` may expose optional scenario-owned collections for nodes and profiles. A dedicated branded `CoupCoordinationNodeId` may be added if consistent with repository ID conventions.

Semantics:

- coordination nodes are coup-only scenario content, not tactical units or reusable military actors;
- node names are authoring/presentation labels only and never branch logic;
- `requiredNodeIds` is an explicit authored necessary set, not a majority, quorum, weighting, force value, rank, or hidden score;
- at most one profile exists per `(countryId, coupFactionId)` candidate;
- no alignment is inferred or authored as a production default;
- existing `ConflictOutcome` remains only a future result sink.

## Required static validation

`assertScenarioDefinition()` must reject at minimum:

- duplicate node IDs;
- missing/unknown node Country;
- empty node name;
- missing profile Country;
- missing coup Faction;
- Faction/Country mismatch;
- Faction without authored `coup` capability;
- duplicate/ambiguous profile for the same coup candidate;
- empty `requiredNodeIds`;
- duplicate required node in one profile;
- unknown required node;
- required node owned by another Country;
- missing successor Government;
- successor Government owned by another Country;
- successor Government already equal to the Country's initial current Government.

Required-node insertion order must not carry semantics. Static validation must not pretend to prove runtime freshness; the future runtime slice must still reject a successor that is stale at actual resolution time.
