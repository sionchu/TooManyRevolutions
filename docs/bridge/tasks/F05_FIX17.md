## 2. Minimum static schema

Follow repository naming/style, but the semantics must be equivalent to:

```ts
interface CoupCoordinationNodeDefinition {
  readonly id: CoupCoordinationNodeId;
  readonly countryId: CountryId;
  readonly name: string;
}

interface CoupCoordinationProfile {
  readonly countryId: CountryId;
  readonly coupFactionId: FactionId;
  readonly requiredNodeIds: readonly CoupCoordinationNodeId[];
  readonly successorGovernmentId: GovernmentId;
}

interface ScenarioDefinition {
  readonly coupCoordinationNodes?: readonly CoupCoordinationNodeDefinition[];
  readonly coupCoordinationProfiles?: readonly CoupCoordinationProfile[];
}
```

A dedicated branded `CoupCoordinationNodeId` may be added if consistent with current `ids.ts` conventions. That ID is static/domain identity only; no runtime node collection is authorized here.

Do not create a generic `MilitaryActor`, `StateApparatusActor`, `Officer`, `Unit`, `CommandNode`, or weighted coordination framework.

### v1 profile uniqueness

Use the narrowest deterministic v1 rule:

- at most one `CoupCoordinationProfile` per `(countryId, coupFactionId)` pair;
- because current Faction identity is Country-owned, duplicate profiles for the same coup Faction should normally reject rather than require a runtime chooser;
- do not introduce priorities or profile selection logic.
